# 0001: Core stack

Date: 2026-10-09. Status: accepted.

## Context

One developer, Android first, offline, a small MVP of 4–5 screens. Chess correctness matters more than anything else. Full reasoning: [PLAN.md, section 3](../PLAN.md#3-proposed-stack).

## Decision

- **Expo SDK 57** (React Native 0.86, React 19.2) with TypeScript in strict mode, started from the `create-expo-app` default template.
- **Expo Router** with a single stack navigator. Routes live in `src/app`.
- **Styling:** `StyleSheet` plus design tokens in `src/constants/theme.ts`. No UI kit.
- **Testing:** Jest through `jest-expo`, React Native Testing Library v14 with `test-renderer` 1.2, and `expo-router/testing-library` for navigation tests.
- **Lint and format:** ESLint (`eslint-config-expo`) with Prettier running as a lint rule.
- **CI:** GitHub Actions runs typecheck, lint, format check and tests on pushes to `main` and on pull requests.
- **Added later, when their milestone needs them:** chess.js (M3), Zustand + AsyncStorage (M8). Stockfish runs only in dev-time content scripts and never ships in the app (M4).

## Consequences

- No custom native code, so the whole MVP runs in Expo Go.
- The web build exists only as a layout preview. It uses single-page output, so it needs no static-rendering workarounds.
- Testing Library v14 is async (`await render`, `await fireEvent.press`). Expo Router's `renderRouter` attaches its route helpers to the object it returns rather than to `screen`, so navigation tests read the pathname from that object.
- `npx expo install` calls Expo's version API. In restricted networks, run it with `EXPO_OFFLINE=1` to use the versions bundled in the `expo` package.
- Typed routes (`experiments.typedRoutes`) are generated by the dev server, so route-path typos fail `npm run typecheck` locally after `npm start`. CI doesn't generate them; the navigation test covers routes there.
- ESLint 9 is the version SDK 57 pins, and npm warns that it's out of support. Move to ESLint 10 once `eslint-config-expo` supports it.

## Alternatives considered

- **Bare React Native CLI:** more native configuration to maintain, for no MVP benefit.
- **NativeWind or Tamagui:** unnecessary for a handful of screens.
- **Detox for end-to-end tests:** heavier than Maestro for the single flow planned in M11.
